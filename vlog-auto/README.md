# vlog-auto

从几十分钟手机素材里自动挑出能用的镜头，导出成编号好的竖屏片段，拖进剪映做后期。

面向的场景：**日常生活 vlog，全程不说话**，原声都是无意义的闲聊和环境噪音。

## 分工

脚本只干枯燥的活，创作交给剪映：

| 谁 | 做什么 |
| --- | --- |
| 脚本 | 读拍摄时间排序、逐段打分、筛掉糊/抖/暗/过曝/静止的废片、裁掉头尾抖动、统一成 1080×1920、按时间顺序编号导出 |
| 剪映 | 自动踩节拍卡点、文本朗读配音、转场、字幕、调色、导出 |

为什么不让脚本一路做到底：卡点和配音在剪映里是所见即所得的，调起来比改脚本参数快得多；而从 40 分钟素材里翻出 100 个能用的镜头，人工做要几小时，脚本几分钟就完了。各自干擅长的事。

## 安装

只需要 ffmpeg 和 numpy。

```bash
./install.sh
```

装不上的话手动来：

```bash
brew install ffmpeg python@3.12
python3.12 -m venv .venv
.venv/bin/pip install -r requirements.txt
```

## 用法

### 第一步：把素材放进 raw/

iPhone 用隔空投送（AirDrop）传到 Mac，**不要走微信**——微信会抹掉拍摄时间，排序就乱了。

### 第二步：分析打分

```bash
.venv/bin/python scripts/analyze.py raw -o shots.csv
```

会打印每个文件的可用片段数，最后生成 `shots.csv`。

### 第三步：人工确认（可选但建议）

用 Numbers 或 Excel 打开 `shots.csv`，只看 `keep` 这一列：`1` 是保留，`0` 是丢弃。机器会故意多留一些（默认比目标多 50%），你扫一眼把不想要的改成 `0`。

其他列是打分依据，供你判断：`score` 是综合分，`sharpness` 是清晰度在本批素材里的排名（0-1），`motion` 是画面运动量。

### 第四步：导出

```bash
.venv/bin/python scripts/export.py shots.csv raw -o selected
```

`selected/` 里就是编号好的片段，外加一份 `剪辑清单.md`（镜头一览 + 写旁白用的提示词）。

### 第五步：在剪映里做后期

1. 新建草稿，尺寸选 **9:16**
2. 把 `selected/` 里的片段**全选拖进素材区**（有编号，顺序不会乱）
3. 加音乐 → 选中音乐轨 → 右键 **自动踩节拍**（卡点段用节拍 II，密一些）
4. 全选素材拖到音乐轨上，自动对齐节拍点
5. 旁白：**文本 → 默认文本 → 粘贴文案 → 选中后点「文本朗读」→ 挑音色**
6. 音量：配音 −3 ~ −6dB，背景音乐 −18 ~ −24dB
7. 转场只在段落之间加（文件名里的 `g1`/`g2` 就是段落），别每个镜头都加
8. 导出

## 常用参数

```bash
# 想出 3 分钟而不是 5 分钟
python scripts/analyze.py raw --target 180

# 镜头短一点，适合快节奏卡点
python scripts/analyze.py raw --shot-len 2.0

# 机器少留一点，不想手动筛
python scripts/analyze.py raw --overshoot 1.0

# 段落划分更细（默认间隔 30 分钟算新段落）
python scripts/analyze.py raw --group-gap 15

# 卡点余量留多一些
python scripts/export.py shots.csv raw --margin 1.5

# 出横屏
python scripts/export.py shots.csv raw --width 1920 --height 1080
```

## 它怎么判断一个镜头好不好

对每条素材按 2.5 fps 抽帧，逐帧算三个指标，再用滑动窗口找出最好的几秒：

- **清晰度**：拉普拉斯算子方差。糊片的高频成分很少，方差就低。绝对值随内容变化大，所以用的是本批素材内的**相对排名**。
- **曝光**：平均亮度 + 过曝欠曝像素占比。太暗（进电梯、装口袋里误拍）或者过曝直接淘汰。
- **运动量**：相邻帧差分。完全不动的（忘了关录像对着地面）淘汰，晃到看不清的也淘汰，手持轻微移动得分最高。

同一条素材里挑出的窗口如果挨得太近，只留分最高的那个，避免几个几乎一样的镜头。最后按段落的素材量分配名额，防止某一段占满整条片子。

**说清楚一点：机器判断的是"技术上是不是废片"，不是"内容有没有意义"。** 一个拍得很稳很清晰的天花板会得高分，一个手抖但记录了重要瞬间的镜头会被丢掉。所以第三步的人工确认别跳过。

## iPhone 素材的两个坑（已自动处理）

- **HDR**：iPhone 默认录杜比视界，直接处理会得到发灰发白的画面。脚本检测到 HDR 会自动做色调映射转 SDR。
- **旋转元数据**：竖屏拍的视频常被存成横向 + 一个旋转标记，不处理会画面躺倒。脚本读取时会正确换算宽高。

横屏素材放进竖屏画布时，两侧自动补模糊背景，不会出现黑边。

## 常见问题

**所有文件都显示「可用片段 0」**
素材可能整体偏暗或者画面太静。放宽一下：`--shot-len 2.0`，或者改 `scripts/analyze.py` 顶部的 `MIN_BRIGHTNESS` 和 `FROZEN_MOTION`。

**提示「读不到拍摄时间」**
文件的 `creation_time` 被抹了，脚本会退回用文件名里的日期，再不行用文件修改时间。顺序可能不准，检查一下 CSV 里的 `shot_at` 列。

**导出很慢**
默认 `--preset medium --crf 18` 是偏高质量的设置。急着看效果就用 `--preset veryfast --crf 23`。

**想先看看效果，手头没素材**
```bash
./make_test_clips.sh testraw
.venv/bin/python scripts/analyze.py testraw -o shots.csv
.venv/bin/python scripts/export.py shots.csv testraw -o selected
```
会生成 12 个覆盖各种情况（清晰/模糊/过暗/过曝/静止/抖动/横屏/HDR）的测试片。

## 关于 AI 配音的音色

剪映自带 30-50 种中文音色，Mac 上直接可用，够用了。

如果想要特定动画角色的音色：本地跑音色克隆（CosyVoice、IndexTTS2 这些）需要 4-8GB 显存的 N 卡，**Mac 跑不动**。而且克隆真实配音演员的声音有法律风险——《民法典》第 1023 条规定自然人声音参照适用肖像权保护，2024 年北京互联网法院已判过 AI 声音侵权案。

实际建议：挑剪映里风格化的音色（古风、戏腔、萌系），**角色感主要来自语气、语速和文案本身，不是音色的精确匹配**。
